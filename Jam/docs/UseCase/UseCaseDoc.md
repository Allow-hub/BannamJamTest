# UseCase層の設計- アプリケーションロジックとビジネスユースケース

UseCase層は、Domain層のロジックを **組み合わせて特定のユースケース（機能）を実現する役割** を担います。  
ユーザーの操作やシステムイベントに応じて、どのようなビジネスロジックを実行するかを定義します。

### ✔ メリット
- アプリケーション固有の機能が明確になる
- Domain層の変更が直接Presentation層に影響しない
- ビジネスロジックがサービスとして再利用しやすい

# UseCase層のサービスおよびイベント処理

## ⬛ モジュール一覧

### AttackProcessor.h
- **役割**: 攻撃処理のビジネスロジックを管理。攻撃判定、ダメージ計算、エフェクト生成要求などを処理。
- **メリット**: 攻撃ロジックを一元化し、再利用性・テスト容易性が向上。
- **デメリット**:
- **制作者**: Allow-hub

### CameraEvent.h
- **役割**: カメラ制御に関するイベントを定義（フォーカス、シェイク等）。
- **メリット**: カメラ挙動をイベントとして抽象化し、UseCase→Presentation の疎結合な連携を実現。
- **デメリット**:
- **制作者**: Allow-hub

### CameraService.h
- **役割**: カメラのユースケースロジック（追従カメラ切替、座標移動指示など）。
- **メリット**: カメラ制御をカプセル化し、Presentation層からの独立性を確保。
- **デメリット**:
- **制作者**: Allow-hub

### EffectEvents.h
- **役割**: エフェクト生成・停止に関するイベント定義。
- **メリット**: エフェクト発生処理をイベント化し、疎結合な連携を実現。
- **デメリット**:
- **制作者**: Allow-hub

### EffectImplementations.h
- **役割**: EffectEvents に対する具体的な処理内容を提供。どのエフェクトをどのタイミングで生成するかを定義。
- **メリット**: エフェクト挙動を集中管理し拡張性が高い。
- **デメリット**:
- **制作者**: Allow-hub

### EnemyFactory.h
- **役割**: 敵キャラクターの生成ロジック。Domain層モデルから初期状態の敵オブジェクトを構築。
- **メリット**: 初期化の複雑さをカプセル化し一元管理。

- **制作者**: Allow-hub
